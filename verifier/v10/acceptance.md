# v10 验收记录（样品请求、库存预占与履约中心）

## 目标与结论

本次升级在 BioMap OS 内落地 Mosaic 逻辑中最关键的第一层：把“我要某个样品”从口头沟通或直接出库，升级为可验证、可预占、可领取、可履约和可审计的正式请求。请求提交时整单校验可用库存；确认发放时才扣减现存量；取消未完成请求时释放预占但不伪造库存变动。

| # | 验收项 | 实现 | 结论 |
|---|---|---|---|
| 1 | 请求建模 | `sample_requests` + 明细、库存预占、履约任务四表 | ✅ 请求、承诺和执行记录分层保存 |
| 2 | 可用量口径 | `可用量 = 现存量 - 其他有效预占`，按 3 位小数统一计算 | ✅ 账面库存与可承诺库存不再混用 |
| 3 | 原子提交 | 锁定请求、样品和有效预占，全部明细校验通过后才整单预占并生成任务 | ✅ 任一明细不足时整单回滚，不产生部分预占 |
| 4 | 预占保护 | 原有入库/出库/调整/外部转出统一经过库存服务；负向操作不得侵占其他请求的有效预占 | ✅ 绕开请求中心的出库也受预占约束 |
| 5 | 履约闭环 | 待领取 → 已领取 → 确认发放；确认时消耗预占并调用库存事务服务扣减数量 | ✅ 数量、库存流水和活动审计保持同一事务 |
| 6 | 幂等性 | 每个履约任务使用稳定的库存幂等键；重复确认返回已处理结果 | ✅ 防止网络重试造成重复扣减 |
| 7 | 取消语义 | 未发生发放时可取消整单，释放有效预占并取消任务；已有发放则拒绝整单取消 | ✅ 取消不直接回写或修改库存数字 |
| 8 | 前台入口 | 新增“样品请求与履约”列表、创建表单、请求详情和工作队列 | ✅ 可从需求建立一直操作到库存扣减 |
| 9 | 样本页集成 | 样本详情显示现存量、已预占、当前可用量，并可直接发起领用请求 | ✅ 用户能在正确的样本层级发起样品请求 |

## 核心业务链

```text
请求草稿
  └─ 提交
      ├─ 锁定样品与有效预占
      ├─ 校验全部明细可用量
      └─ 整单预占 + 每明细生成一个发放任务
          └─ 领取任务
              └─ 确认发放
                  ├─ 保护其他请求预占
                  ├─ 扣减 samples.quantity
                  ├─ 写 stock_transactions
                  ├─ 消耗 inventory_reservations
                  └─ 写 activities 哈希链审计
```

## 已知边界

- 首期履约粒度为“一个请求明细对应一个发放任务”，还未加入波次拣选、容器/孔板级拆分、条码交接、自动化工作站队列和设备结果回写。
- 首期预占不设自动过期时间；取消由业务用户显式执行。后续可在策略确认后增加到期提醒与受控释放。
- 已完成部分发放的请求不允许整单取消；后续如需退样，应新增独立、可审计的退回操作，而不是回改请求状态或库存余额。
- 内置浏览器已确认 3100 服务可加载登录界面；演示请求的登录、查询和业务状态通过同一服务的真实 HTTP/tRPC 接口验证。
