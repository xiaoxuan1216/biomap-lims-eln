# v14 · Mosaic-style Run 数据流转

日期：2026-09-09。

## 交付范围

在实验发起向导中，完成流程与样本选择后即时显示“计划预览 · 尚未冻结”；选择设备时同步补齐设备状态。创建 Run 后，详情页默认进入“数据流转”，以五段泳道呈现需求上下文、样本与物料、Frozen RunPlan、节点与设备、结果与回库，并可点击对象检查字段和证据来源。原有运行步骤、资源、参数、就绪检查与受控操作保留在“执行详情”页签。

## 事实边界

- 发起前预览只来自当前表单，明确标注未保存、未预占、未预约、未执行。
- Run 详情区分冻结快照、当前库存/储位和运行节点状态；资源名称与标识优先读取不可变样本快照。
- simulation 的 completed 只表示模拟状态推进完成，不代表真机执行或实验结果已产生。
- 当前没有与 Lab Run 绑定的 Measurement、Raw Data、ResultPackage 或回库记录，因此结果阶段保持“尚未记录”，不生成演示结果卡。
- 证据来源限定为 RunPlan、运行资源、库存/储位、样本请求/预占/履约、样本谱系、运行节点和设备预约记录。

## 验收步骤

1. 打开 `/runs/new?workflowId=1`，完成运行信息并进入样本选择；勾选实验样本后应出现黄色“计划预览 · 尚未冻结”泳道。
2. 进入设备与参数步骤，预览中应显示真实设备选择和当前台账状态；未完成兼容性校验时显示待配置或需复核。
3. 打开 `/runs/4`，默认页签应为“数据流转”，并显示五段泳道及右侧对象检查器。
4. 点击样本对象，检查冻结时数量、冻结位置、当前位置、角色和证据；点击节点，检查设备、驱动、方法与当次参数。
5. 结果区必须显示“尚未生成结果包”；模拟提示必须明确不代表真机执行或真实实验结果。
6. 切换“执行详情”，原有模拟启动/推进、节点列表、参数、就绪性和快照哈希仍可使用。

## 自动检查

运行 `node --import tsx verifier/v14/api-check.mts`。脚本检查四个后端事实阶段、对象与连线引用、证据来源白名单、simulation 资源隔离，以及没有伪造结果节点；输出写入 `verifier/v14/api-checks.json` 和 `verifier/runs/v14-mosaic-data-flow.log`。
