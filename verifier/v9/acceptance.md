# v9 验收记录（仪器运行控制中心工程化升级）

## 目标与结论

本次升级将原先的展示型单页原型重构为可演进的仪器运行控制中心。界面明确区分 `demo` 与 `live` 数据来源；正式模式在 Run、审批、遥测、谱系等服务未接入时保持锁定，不再使用静态数字或演示数据伪装系统正常。

| # | 验收项 | 实现 | 结论 |
|---|---|---|---|
| 1 | 工程边界 | 页面仅编排工作区；领域模型、tRPC 控制器与七个界面组件分离 | ✅ 页面不再承载全部业务逻辑 |
| 2 | Live / Demo 隔离 | `/instrument-agent-preview` 显式使用 demo 适配器；正式路由只读取正式接口，查询为空或失败均不回退演示数据 | ✅ 数据来源可见且不可混用 |
| 3 | 能力门禁 | 集中声明库存事务、库位盘点、参数审批、运行控制、遥测、谱系和 Agent 指令能力 | ✅ 未接能力默认禁用并解释原因 |
| 4 | 运行状态机 | 建立 draft → ready → running → review → completed 阶段、进度和样本/审批/设备门禁 | ✅ Demo 可验证；Live 在后端接入前锁定 |
| 5 | 参数风险与审批 | 参数基线/建议/依据/风险分层、审批确认和版本锁定拆为独立工作区 | ✅ 正式模式明确标注为参考模板，不能形成执行版本 |
| 6 | 设备可信度 | Demo 才显示健康分与演示遥测；Live 仅显示设备台账、预约与校准登记，不推断 Edge 心跳 | ✅ 消除伪实时与伪健康分 |
| 7 | 精确扫码 | 新增 `sample.resolveBarcode` 服务端精确解析，不受 500 条列表上限影响 | ✅ 未命中当前列表时仍可精确查找 |
| 8 | 重复扫码防护 | `sample.transact` 暴露并透传 `idempotencyKey`；同一失败重试复用请求键，提交期间锁定表单 | ✅ 服务端幂等能力进入正式扫码链路 |
| 9 | 库存安全 | Demo 超量出库抛错，不再静默截零；Live 继续复用库存服务的负库存与方向校验 | ✅ 库存不变量保持 |
| 10 | 异步与空态 | 样本、设备、审计和数据谱系均有 loading / error / empty / unavailable 表达及重试入口 | ✅ 接口故障不再表现为“正常” |
| 11 | 可访问性与响应式 | 扫码类型使用 `aria-pressed`，表单 label/错误关联，操作 pending 锁定；表格和场景栏支持横向滚动 | ✅ 基础键盘、读屏与窄屏路径覆盖 |
| 12 | 自动化测试 | 新增条码归一化、四种扫码方向、库存不足、运行门禁、阶段推进和风险汇总测试 | ✅ 11 个测试文件、47 项测试通过 |

## 软件结构

```text
InstrumentAgent page
├── useInstrumentAgent       数据源适配、能力门禁、查询与 mutation 协调
├── model                    场景契约、运行状态机、扫码与风险纯函数
└── components
    ├── WorkspaceHeader      数据来源与运营摘要
    ├── SceneRail            四类仪器上下文与设备台账/遥测边界
    ├── RunControl           运行阶段、门禁、遥测与指令入口
    ├── ReadinessPanel       执行前检查、设备健康与审计事件
    ├── ParameterWorkbench   参数差异、证据链与审批
    ├── SamplesWorkspace     样本台账与交接入口
    ├── ScanDialog           扫码枪输入、精确解析与库存事务
    └── DataWorkspace        Demo 跨仪器数据谱系
```

## 已知边界

- 真实仪器 Run 聚合、参数建议版本、电子审批、Edge 心跳/事件、原始数据回收和跨仪器谱系接口仍待实施；对应正式界面已锁定，不展示伪造数据。
- 现有 `sample.transact` 可安全表达数量入库/出库，但库位原子转移、交接人、目标设备、Run ID 和库存版本仍需新的完整扫码交接接口。
- 当前工作区未配置数据库与实机连接，本轮未执行正式库存写入或厂商设备联调。
- `media_demo/` 为用户原有未跟踪目录，本次未修改。
