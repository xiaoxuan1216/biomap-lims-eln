# V17 原始文件接入 — 软件验收

2026-09-17。目标仍是客户抗体研发真实流程；本轮解决原始文件 2 MB 限制，不作为物理实验或客户仪器适配验收。

## 已实现

- 任务内使用二进制流上传，默认上限 100 MiB。`BIOMAP_EVIDENCE_MAX_MB` 可配置为 1–1024 的整数，前端读取服务端上限；实际验证的最大文件为 100 MiB，未将更高配置视为性能承诺。
- 上传显示进度与保存状态，可以取消；网络失败后刷新文件列表，便于确认服务端是否已保存。相同任务、步骤和 SHA-256 的重传沿用原记录。
- 接收前检查登录、来源、角色、当前负责人及步骤状态；传输结束后再次在事务内校验。不会在传输期间占用任务数据库锁。
- 文件以临时文件接收，逐块限额与计算 SHA-256，完成后同步磁盘并改名；数据库引用与活动审计同事务提交。失败或取消的临时文件被清理。
- 下载需要登录，校验大小与 SHA-256 后按附件返回。开发服务的静态路径和 `/@fs` 入口不能直接访问原始文件。
- `0021_streamed_run_evidence.sql` 仅使原 Base64 列可空并增加 `storageKey`；既有文件继续按原方式读取。旧 tRPC 小文件入口仍兼容 2 MB，产品界面已切换新入口。

## 存储与恢复

默认目录为仓库下 `.data/run-evidence`，本机 Docker 中为 `/app/.data/run-evidence`，通过现有仓库 bind mount 持久化。`.gitignore` 和 `.dockerignore` 已排除 `.data`。不要把该目录放进 `public` 或 `dist/public`；配置校验拒绝这两类路径。

上线需要为 `BIOMAP_EVIDENCE_DIR` 配置持久目录，并将数据库、该目录及配置共同纳入备份。多实例需访问同一持久文件目录；本轮没有实现外部对象存储或多地域复制。

默认 namespace 从数据库主机与库名派生，避免本地正式预览与 QA 库共用文件。备份清单应保存 namespace；更换数据库地址或库名恢复时，用 `BIOMAP_EVIDENCE_NAMESPACE` 保持原 namespace，并先核对工作区归属。不要把新工作区指向其他工作区的 namespace。

建议恢复顺序：停止写入 → 同时备份数据库、文件目录和配置 → 恢复至隔离环境 → 设置原 namespace → 运行版本化迁移 → 对所有登记文件逐一核对存在性、大小和 SHA-256 → 用原权限验证任务、结果、签署记录及文件下载 → 确认后恢复服务。不要在未核对文件目录时只恢复数据库并宣布记录完整。

数据库提交结果不明时可能留下未引用的完整文件；系统保留它而不是冒险删除可能已提交的证据。此类文件只能经数据库引用核对后另行处理，本轮未自动清理。磁盘容量、备份恢复和多实例运维仍需在客户部署环境验收。
