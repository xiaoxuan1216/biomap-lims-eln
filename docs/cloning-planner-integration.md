# 分子克隆动态排板与 BioMap OS 产品整合

排板已内嵌到现有 BioFlow 编辑器和节点属性面板。用户从项目或已有业务流进入，在 `/workflows/:id` 内查看、调整和保存孔板方案，自动沿用项目、流程和当前节点上下文。独立 HTML 保留为离线开发示意。

## 产品主线

```mermaid
flowchart LR
    Project[项目 / 实验需求] --> Flow[BioFlow 业务流与节点]
    Flow --> Plan[分子克隆排板方案]
    Plan --> Compare[容量校验 / 条件推荐]
    Compare --> Snapshot[方案版本 / 孔位快照 / 审计]
    Snapshot -.执行前需要绑定.-> Materials[真实样本 / 试剂用量 / 备料履约]
    Materials -.确认 SOP 与设备后.-> Run[仪器属性智能体 / 设备执行]
    Run -.过程与结果.-> ELN[ELN / 原始数据 / QC]
    ELN -.审核后.-> Delivery[质粒交付 / 菌种归档]
```

实线为本次落地的规划与记录关系；虚线沿用整体产品已有模块，但本次没有自动创建备料请求、运行任务、实验结果或放行记录。节点仍沿用原有负责人、设备绑定、参数、ELN 和子流程功能；真实执行仍需完成来源、用量、SOP、设备及结果绑定。

## 现有功能中的操作方式

1. **BioFlow 编辑器**：已有克隆相关节点的业务流显示“流程图 / 孔板与样本”视图。切换发生在同一编辑器内，保留流程图状态和未保存的排板草稿。调整样本数、候选数和特殊条件后，所有阶段重新排布。
2. **节点属性面板**：PCR、组装、转化、挑菌、质粒提取等既有节点直接显示对应阶段的 96 孔板。支持换板、悬停 / 键盘焦点看样本信息、点击追踪和孔详情，无需离开流程图。
3. **同一版本贯穿节点**：节点预览和展开后的全流程排布使用同一已保存版本。节点上的数字是流程方案摘要，不是设备已执行或节点实际产量。每次保存的 `nodeKey` 记录操作来源节点，排板范围始终是整个业务流。
4. **项目业务流卡片**：在原有进度与节点条下展示“孔板与样本 · Vn · 样本数 / 板数”，子流程的方案附在子流程下。点击回到原业务流的孔板视图。
5. **版本与上下文**：默认打开当前流程最近的已保存方案；可原位切换历史版本、另存新版本和导出。不再重新选择所属流程。背景刷新版本列表不会自动丢弃当前草稿。流程图有未保存结构修改时，先保存流程图再展开排板。

全局侧栏的独立排板项、BioFlow 列表上的独立按钮、项目页的独立排板区和排板页的跨模块跳转卡片已移除。旧 `/cloning-planner?planId=…` 链接兼容跳转到关联业务流；无上下文的旧链接回到流程列表。

现有流程内示例：`/workflows/22?view=plates&nodeKey=n3`。`view` 控制图 / 孔板显示，`nodeKey` 指定当前节点上下文，`planId` 固定历史方案；切回流程图时保留后两个参数。

示例已建立在现有“重组抗体表达与表征”项目下，业务流名为“演示：分子克隆排板与 BioFlow 集成”，保存 96 目标的紧凑和推荐方案。样本与物料为虚拟规划数据，没有混入库存或形成真实执行结果。

## 今天的能力如何纳入整体产品

| 产品对象 | 本次实现 | 执行前仍需确认 |
| --- | --- | --- |

| 条件推荐 | 对照预留、反应板避边、候选成组、按列遍历、尾板均衡；显示额外板数 | 设备通道能力、移液路径与经过确认的实验规则 |
| 样本流向 | 交互孔板、悬停详情、目标锁定、跨板切换、全板总览 | 实际转移事件及执行产物身份 |

| 仪器执行 | 排板与节点已有设备绑定和参数处于同一编辑器；计划可导出 | SOP / 方法版本、体积、库存门禁、RunPlan 与设备接收确认 |
| ELN / QC | 明确待执行和待选克隆语义；沿用节点既有 ELN 关联 | 执行记录、原始数据、签署审核及放行结果 |
| 审计与版本 | 服务端生成、不可变快照、SHA-256 校验、幂等保存、并发版本检查 | 正式实验审批与组织 SOP |

## 排板规则

- A / B / C 各 N 个来源；E / F / G / H 各 N 个反应或样本；J / K 各 N×C 个候选；N 测序预留 2N 份；L / M / O / P 各 N 个位置。
- E / K 每板对照为 0、2、4 孔。避边仅作用于 E / G / K；内圈为 B02:G11 的 60 孔。对照孔、避让孔与样本孔不得重叠。
- 紧凑方案逐行填板；推荐方案按用户偏好成组、列遍历和尾板均衡。
- 同目标候选同板可能增加用板量，例如 94 目标 × 3 候选，K 每板 2 对照时，紧凑 K 为 3 板；成组 K 为 4 板。界面明确展示差异。
- “更优”只针对当前选择的排布目标，不声称实验效果或设备路径最优；按列顺序也不保证整列可以多道同步移液。
- L 从 J 候选中择一的关系为 `conditional`，K 结果为 `result`；未执行筛选前不绑定具体 `cloneId`。
- O 的物料来源是 M 质粒母样，P 来自 L 培养物；N 测序提供结果依据，不作为交付产物来源。

## 数据与接口

新增表 `cloning_layout_plans` 通过版本化迁移 `0010_cloning_layout_plans.sql` 创建。没有修改已有样本数量、库存服务、ELN 签署机制或 BioFlow 节点保存机制。

方案字段包括：`workflowId`、`nodeKey`、`projectId`、关联名称快照、`version`、`engineVersion`、`mode`、样本 / 板数摘要、完整 `snapshot`、`snapshotHash`、`requestHash`、`idempotencyKey` 和创建人。

| tRPC 接口 | 权限与行为 |
| --- | --- |
| `cloningLayout.list` | 已登录用户；可按项目 / 流程过滤，返回最近 100 条摘要 |
| `cloningLayout.byId` | 已登录用户；校验保存快照 SHA-256 后读取原始版本，不通过当前算法重算历史 |
| `cloningLayout.save` | user / reviewer / admin；服务端校验参数，生成完整计划，并在同一事务内保存快照与活动记录 |

保存按工作流串行分配版本，客户端带 `expectedVersion`。重复请求使用同一幂等键返回原版本；同一键改写内容、旧版本写入或并发写入会得到冲突。已完成 / 归档的流程不能新增计划。节点关联采用稳定的 `(workflowId, nodeKey)`，保存排板不会调用 `saveGraph`、重建节点或覆盖节点参数。

生成的 `PLAN` 容器和虚拟样本编码只在所属方案快照内有意义，不能直接作为真实库存容器 / 样本主键。JSON 导出携带关联信息；CSV 导出所有物理孔，包括空孔、对照孔和避让孔。D 物料与 I 平皿在 JSON 中单独记录。
